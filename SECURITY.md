# Security and private reports

Do not disclose exploit details, credentials or private saves in public issues.

Before public launch, maintainers must enable GitHub private vulnerability reporting and verify the **Security → Report a vulnerability** flow. If that entry is not available, do not open a public exploit report; wait for the private channel to be configured.

Ordinary crashes and gameplay defects belong in Issues. Account and payment support needs a separate private support contact, configured before launch. This scaffold intentionally contains no invented email address.
